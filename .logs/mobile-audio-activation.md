# Mobile sound activation

Touch activation now listens for pointerup/touchend rather than attempting unlock on touch pointerdown. Launch/resume button actions explicitly request activation within the click handler. Resume attempts have a 1.5 second wait bound, and later gestures retry even when an earlier request is pending. Preloading starts only once. Audio controls offer Enable sound while the context is not running, with a confirmation cue on successful explicit recovery; saved mute and volume choices are preserved.

Build passed. Two existing music tests passed (settings, pause/resume, loop duplication), and two new Chromium touch tests passed (first Launch tap produces music and effects with nonzero output; simulated suspended/pending resume recovers via Enable sound). The recovery test explicitly suspends the real context while withholding the resume promise, since Chromium can automatically start a context created in a valid gesture.
